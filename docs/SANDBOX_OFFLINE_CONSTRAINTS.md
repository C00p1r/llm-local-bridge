## 二、在斷網沙盒內「無法解決」的事項

### A. 任何需要即時網路的能力
1. **執行期套件安裝**：`pip install` / `npm install` / `apt-get install` 全部失敗（apt-get 存在但抓不到來源）。
2. **直接網路請求**：`curl` / `wget` 不存在，且就算存在也會被 `--network none` 阻斷。
3. **沙盒內直接 git 操作**：`git` 不存在；即使存在也無法連 GitHub。
4. **呼叫外部 API**：無法在沙盒內做任何 REST／HTTP 呼叫。
5. **下載測試資料／模型／資料集**：無法在執行期取得。

### B. 需要沙盒內不存在的執行環境
6. **JS / TS 真正的語法或 lint 檢查**：`node` 不存在，無法跑 `node --check`、eslint、tsc。
7. **ripgrep 加速檢索**：`rg` 不存在（但已有 Python 原生 fallback 可替代，見下）。
8. **需要瀏覽器／無頭瀏覽器的測試**：無法安裝 Playwright/Puppeteer。
9. **原生編譯（需下載標頭／依賴）**：如 `gcc` 編譯第三方庫。

## 四、關鍵結論

### 1. 真正的「死路」只有三類
- **執行期安裝軟體**（pip/npm/apt）
- **執行期網路請求**（HTTP/API/下載）
- **沙盒內原生 git／node 等缺失二進位檔**

### 2. 這些死路「大多已被架構繞過」
- **git 需求** → 早就以「主機端代管（`handle_github_action`）」解決，沙盒內根本不需要 git。
- **rg 需求** → 已有 Python fallback，非硬依賴。
- **語法驗證需求** → 可由主機端執行（主機有 node/git）或映像擴充。

### 3. 與網路無關、可 100% 在現狀解決的改進
- **#1 JSON 解析強化**（後端寬鬆解析 / 提示詞約束）
- **#3 git_push 自動補本地同步**
- **#4 file_undo 工具**
- **#5 apply_patch（unified diff）工具**

### 4. 唯一需要「一次性主機動作」才能解的
- **擴充沙盒映像**（預裝 node / git / rg）：需在有網路的主機端 `docker build` 或 `docker pull`，屬**部署階段**動作，非執行期。

---

## 五、實務建議

> **原則：凡涉及網路或缺失二進位檔者，一律「拉回主機端」處理；凡屬純文字／檔案邏輯者，留在沙盒或後端即可。**

- 需要網路的能力 → 走主機端代理（如同現有 git 模式），不要試圖在沙盒內解。
- 需要 node/rg 的能力 → 要嘛主機端執行，要嘛換映像；不要期待執行期安裝。
- 其餘解析、檔案、patch 類改進 → 完全不受斷網影響，可立即實作。
